# Full pinned dependency set for building the Docker image (Python 3.11,
# matching docker/api.Dockerfile's `python:3.11-slim` base and CI's
# python-version: "3.11").
#
# WHY THIS FILE EXISTS (see docs/DECISIONS/0016 for the full account):
# a real, previously-undiscovered dependency conflict, found for the first
# time during genuine Docker build verification (no prior session had a
# working Docker daemon to catch it, and this project's local dev/.venv has
# always used Python 3.13, never 3.11): `pyannote-core` (a transitive
# dependency of `pyannote.audio`) declares `numpy>=2.0`, while `funasr`
# declares `numpy<2` - a real, unresolvable conflict for pip's fresh
# dependency resolver on Python 3.11, which either backtracks into
# ancient, Python-3.11-incompatible numba/lightning releases trying to
# reconcile it (exhausting itself with a real `resolution-too-deep` error),
# or fails outright with `ResolutionImpossible`.
#
# In practice, pyannote-core's numpy>=2.0 floor is NOT a real runtime
# requirement for anything this project actually uses - proven directly:
# every real diarization test in this project's history has run correctly
# against numpy 1.26.4 (this project's local .venv has always had numpy
# <2 installed, satisfying funasr, with pyannote-core's stricter floor
# simply unmet and harmless - `pip check` reports it as a metadata warning,
# never a runtime failure). This file's exact pinned versions are the
# emotion2vec+/diarization real-model-verified working combination from
# that same local .venv, frozen so pip's resolver never has to search for
# them itself: `pip install --no-deps -r docker-constraints.txt` installs
# every package at exactly this version with zero dependency resolution
# (deliberately - the whole point is to skip the search that fails), and
# is verified to import correctly together (numpy, scipy, numba, librosa,
# pyannote.audio, funasr, faster_whisper, torch, transformers, and the
# core FastAPI/SQLAlchemy/Celery/Redis/boto3 stack all real-imported
# successfully under this exact combination on a real Python 3.11
# interpreter before this file was committed).
#
# Regenerate when pyproject.toml's dependencies change materially:
#   apps/api/.venv/bin/pip freeze | grep -v -e voxmind -e '^-e ' -e audioop-lts > apps/api/docker-constraints.txt
# (audioop-lts is Python-3.13-only - the local .venv's Python 3.13 needs
# it as a stdlib backport; Python 3.11 still has the real stdlib module
# and must not receive this line, or pip refuses it outright.)
