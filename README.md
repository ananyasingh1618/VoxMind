# VoxMind

A multimodal conversational intelligence platform: speech, emotion, language, memory, retrieval-augmented generation, and voice - built incrementally, in public, as a production-style portfolio project.

**Status: VoxMind is in production freeze** (see [docs/FINAL_PRODUCTION_FREEZE.md](docs/FINAL_PRODUCTION_FREEZE.md) for the full record) as a **production-ready local/containerized system** - not a claim of a live, publicly deployed production service. Formal STT/emotion/retrieval/grounding/system evaluation is real and has actually been run (see [docs/evaluation.md](docs/evaluation.md)); background pipeline work runs through a real Celery + Redis worker as an alternative to the default in-process runner, with measured memory-robustness behavior and a real stale-run reconciliation mechanism (see [docs/celery.md](docs/celery.md)); Redis-backed rate limiting protects the API from abuse (see [docs/rate_limiting.md](docs/rate_limiting.md)); object storage supports both local-filesystem and real S3/MinIO backends (see [docs/storage.md](docs/storage.md)). **The full Docker stack has been genuinely built and run** - Postgres+pgvector, Redis, MinIO, the API, and a real Celery worker, all in real containers, with a real end-to-end pipeline run (upload → STT → diarization → alignment) completing successfully across containers - see [docs/docker.md](docs/docker.md). **A real browser walkthrough** (Playwright, not source inspection) exercised auth, navigation, audio upload/transcription, analysis display, analytics/evaluation dashboards, knowledge upload, the voice-turn control, and error handling against the real running app - two real bugs were found and fixed in the process (a session-loss bug from an overly-narrow cookie path, and a "New conversation" button that created a real conversation but never navigated to it) - see [Current capabilities](#current-capabilities) and `docs/FINAL_PRODUCTION_FREEZE.md`. **GitHub Actions CI has now actually run and passed for real**, once GitHub CLI authentication became available: both the `frontend` and `backend` jobs completed successfully on a real push to `main` - see the badge/run at [github.com/ananyasingh1618/VoxMind/actions](https://github.com/ananyasingh1618/VoxMind/actions). See [Current capabilities](#current-capabilities) below for exactly what runs today.

## Current capabilities

What actually works right now, end-to-end, against a real Postgres database:

- Email/password registration and login, with bcrypt password hashing
- JWT access tokens + rotating, reuse-detecting refresh tokens (see [docs/architecture.md#authentication](docs/architecture.md#authentication))
- CSRF-protected refresh/logout, "log out" vs. "log out everywhere"
- Conversations and messages: create, list, retrieve, delete, with ownership enforcement and cascade delete
- Real audio upload (wav/mp3/m4a/ogg/webm, content-sniffed not trusted-by-header), real ffmpeg-based preprocessing, and **genuine faster-whisper speech-to-text** - verified end-to-end with real synthesized speech, not mocked (see [docs/audio.md](docs/audio.md))
- Real pyannote.audio speaker diarization integration - implemented and unit-tested, but not executable in this repository's current environment (the model is gated on Hugging Face and no token is configured); when unavailable, the pipeline degrades gracefully and still produces a transcript rather than faking speaker labels
- A deterministic, fully-tested transcript/diarization alignment algorithm
- Real acoustic feature extraction (librosa) and **genuine Wav2Vec2 speech embeddings** (Hugging Face `facebook/wav2vec2-base`), feeding a real, trainable PyTorch emotion classifier - **trained and evaluated on the real RAVDESS speech-emotion corpus**: 67.2% test accuracy / 0.690 macro F1 across 8 emotion classes on a genuinely held-out, speaker-independent test set (chance = 12.5%). Verified end-to-end with a real prediction on a real held-out audio sample through the live API. See [docs/emotion.md](docs/emotion.md) for the full metrics, confusion matrix, and honest limitations (an acted, single-speaker, English-only corpus - not a claim of real-world conversational generalization)
- A storage abstraction (local filesystem + S3/MinIO-compatible), genuinely wired to audio, model-artifact, and knowledge-document storage
- **Real NLP**: sentiment (`cardiffnlp/twitter-roberta-base-sentiment-latest`) and named-entity recognition (`dslim/bert-base-NER`) via genuine Hugging Face models, plus deterministic intent/topic extraction - see [docs/nlp.md](docs/nlp.md)
- **A real semantic-vocal incongruence signal**: compares real per-turn sentiment against real per-turn emotion predictions - explicitly not a lie detector, and never framed as one (enforced by a database `CHECK` constraint, not just a comment)
- **Real conversation memory**: a bounded recent-turns window plus a rolling long-term summary, generated by a real LLM when configured or a genuine deterministic extractive-summarization algorithm when not - see [docs/memory.md](docs/memory.md)
- **Real retrieval-augmented generation**: document upload/parsing (.txt/.md/.pdf) → deterministic chunking → genuine sentence embeddings (`sentence-transformers/all-MiniLM-L6-v2`) → real pgvector cosine search + real PostgreSQL full-text search, fused via reciprocal rank fusion, with real cross-encoder reranking (a genuine float32-precision bug in this environment was found and fixed - see [DECISIONS/0007](docs/DECISIONS/0007-reranker-float64-precision-bug.md)) - see [docs/rag.md](docs/rag.md)
- **A real, credential-gated LLM provider abstraction** (Anthropic and OpenAI, structured output forced via tool-use/function-calling) with application-side citation validation and grounding - a fabricated citation is filtered out before it ever reaches the client, and `grounding_status` is computed by the app, never self-reported by the model. No API key is configured in this environment, so the network call itself is implemented and unit-tested but not exercised end-to-end here; every credential-independent part of the pipeline (ingestion, retrieval, ranking, grounding) was verified live against a real running server - see [docs/rag.md](docs/rag.md)'s verification section
- **A real, end-to-end conversational voice loop** (Phase 5): press the microphone, speak, and VoxMind genuinely transcribes it (Whisper), analyzes it (emotion/NLP/incongruence), retrieves and answers (RAG/LLM), speaks the answer back (real local text-to-speech, `facebook/mms-tts-eng` - no credentials needed), and can be interrupted mid-response at any point - all streamed live as Server-Sent Events, with genuinely measured per-stage latency (STT/analysis/retrieval/LLM/TTS/total) shown in the UI. A real bug in the interruption handling was found and fixed via live testing, not assumed away - see [docs/voice.md](docs/voice.md) and [DECISIONS/0009](docs/DECISIONS/0009-voice-loop-cancellation.md)
- **A dedicated guardrail layer** (Phase 6) between the LLM and everything downstream of it: real prompt-injection scanning filters malicious document content out of retrieval *before* it reaches the model, real structural/citation validation catches inconsistent responses, and a real safety check (OpenAI's moderation API when configured, a real deterministic keyword fallback otherwise - never skipped) can replace an unsafe answer with a safe refusal. Every decision is logged. A real correctness bug (an unvalidated answer could leak through to API responses even after being blocked) was found and fixed - see [docs/guardrails.md](docs/guardrails.md)
- **A real analytics dashboard** (Phase 6) built entirely from genuine aggregate queries over your own data - latency per pipeline stage, emotion/sentiment/intent distributions, mismatch events, retrieval usage, grounding status, model versions, and failure counts - with honest empty states, never fabricated numbers, when there's not enough data yet
- **Real, explainable conversation insights** (Phase 6): a per-message intelligence timeline plus a small set of summary insights that explicitly separate factual, model-attributed observations from hedged, non-diagnostic interpretations - never psychological or medical language
- A dark, responsive React app shell: auth pages, conversation list, a conversation workspace with the real voice control described above, a real audio upload/transcription panel, a real emotion/NLP/incongruence analysis panel, a real knowledge panel (document upload, ask-a-question flow showing retrieved sources, ranked evidence, the generated answer, citations, grounding status, and the guardrail decision), a real analytics dashboard, a real per-conversation insights/timeline view, and a real evaluation dashboard
- **Real, versioned STT/emotion/retrieval/grounding/system evaluation** (Phase 7): genuine WER/CER against a small versioned dataset (real faster-whisper transcription, not mocked), genuine RAVDESS emotion re-evaluation reusing the unmodified Phase 3 protocol, genuine Recall@K/Precision@K/MRR/nDCG against a small hand-labeled retrieval test collection built specifically for this evaluation, genuine citation-validity/grounding-status aggregation over real LLM generations, and genuine p50/p95 latency/completion-rate/failure-rate over real persisted execution data - every evaluation run is persisted (never overwritten) in `evaluation_runs` and surfaced on a real dashboard. Metrics that require ground truth this project doesn't have (e.g. answer-content faithfulness beyond citation-ID validity) are explicitly reported `unavailable`, never fabricated - see [docs/evaluation.md](docs/evaluation.md) for exact commands and exact real results

- **A real Celery/Redis background-job cutover** (Phase 9): every pipeline stage can run through a genuine Celery worker process instead of the default in-process runner, verified against a real locally-installed Redis broker and a real worker subprocess (not just code inspection) - real queue routing (expensive ML work separated from cheap deterministic work), real retry/backoff for transient failures only, a real idempotency guard against task redelivery, and real health/readiness endpoints that ping an actual live worker rather than just checking the broker port. Zero pipeline call sites changed - selecting it is a config flag, exactly as the Phase 1 `TaskRunner` contract was designed to allow. See [docs/celery.md](docs/celery.md)

- **Redis-backed rate limiting**: protects the API from abuse and runaway expensive requests - four endpoint categories (auth, expensive ML/LLM work, knowledge ingestion, ordinary traffic), each independently configurable, a real distributed fixed-window counter backed by Redis (correct across multiple API processes, not just one), real `429`/`Retry-After` responses, and an explicit, configurable fail-open/fail-closed policy if Redis itself becomes unreachable. See [docs/rate_limiting.md](docs/rate_limiting.md)
- **Real S3/MinIO object storage verification**: the existing local-filesystem/S3 storage abstraction was verified against a genuinely live MinIO instance (not just the existing moto-based unit coverage) - real connect/authenticate, upload, download with exact content verification, delete, and correct missing-object handling, all through the actual `S3StorageBackend` class. See [docs/storage.md](docs/storage.md)
- **A real, fully-verified Docker stack**: Postgres+pgvector, Redis, MinIO, the FastAPI API, and a real Celery worker, all built and run as real containers (not just inspected compose files) - real health/readiness, a real migration run against a fresh containerized database, and a real end-to-end pipeline request (upload → STT → diarization → alignment) completing successfully across the API and worker containers. Three real bugs were found and fixed in the process: a missing `.dockerignore` that would have copied a real secrets file into an image layer, a Python-3.11-specific dependency conflict that blocked the image from building at all, and a missing Redis URL override that silently disabled rate limiting inside containers. See [docs/docker.md](docs/docker.md)

What does **not** exist yet: a full accessibility audit (beyond the reduced-motion/responsive fixes already verified) remains open. See `docs/FINAL_PRODUCTION_FREEZE.md` for the complete, categorized list of what is real-verified, credential-gated, and unverified.

## Getting started

See [docs/development.md](docs/development.md) for prerequisites, environment variables, three ways to run the stack locally, migrations, and test commands.

Quick version (non-Docker path, fully verified). Note: `pip install -e ".[dev]"` now also installs faster-whisper, pyannote.audio, librosa, transformers, pgvector, pypdf, anthropic, and openai (the ML libraries pull in PyTorch) - a multi-GB dependency set that takes a few minutes; ffmpeg must also be installed on the host (`brew install ffmpeg` / `apt-get install ffmpeg`). MLflow tracking is a separate opt-in extra: `pip install -e ".[dev,ml-tracking]"`. To use a real LLM provider, set `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` (a developer-console API key, not a Claude/ChatGPT chat subscription) - without one, `/ask` still runs the full retrieval pipeline and honestly reports `grounding_status="unavailable"` rather than fabricating an answer. For the complete containerized stack (API, worker, and frontend all in real containers, no local Python/Node setup at all) see [docs/docker.md](docs/docker.md) instead.

```bash
# 1. Infra
docker compose -f docker/docker-compose.yml up -d

# 2. Backend
cd apps/api
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env   # fill in JWT_SECRET_KEY
alembic upgrade head
uvicorn voxmind.main:app --reload

# 3. Frontend (separate terminal)
cd apps/web
npm install
npm run dev
```

## Project principles

This project is built under an explicit set of constraints (see `docs/DECISIONS/` for the record of decisions made under them): no fabricated AI outputs, no hardcoded scores, no claimed-but-unmeasured metrics, no placeholder endpoints presented as real. If a feature isn't built yet, the UI and docs say so.
